# jianying-autocut：素材文件夹 → 讲故事的剪映粗剪草稿

`S=<本 SKILL.md 所在目录>/scripts`（npx skills 或软链安装时就是 `~/.claude/skills/jianying-autocut/scripts`；插件安装时在插件缓存目录里），一律 `uv run --script $S/<x>.py` 调用（依赖写在脚本头里，首次运行自动装）。
工作目录 `W` 默认是 `<素材目录>/_autocut`；各步只通过 W 里的文件衔接，任何一步都能单独重跑。

## 多台设备混拍：先让用户自己校正时间

章节内镜头大体按拍摄时间排序。几台相机 / 手机的时钟没对齐时，顺序会乱、甚至被误判成不同行程
（实测：一台手机日期慢了近一个月）。本技能不自动校时：发现拍摄日期与内容对不上时，提醒用户先用
相机自带功能或 `exiftool` 修正拍摄时间再跑；也可以只靠故事脚本的章节顺序来讲时间线。

## 先分模式

| 用户的情况 | 走哪条 |
|---|---|
| 还没拍，要拍摄脚本 / 拍摄清单 | **模式 A**，见下一节 |
| 已经拍好，按模式 A 的脚本页面剪 | **模式 B**：第 0–3 步照常，第 4 步走「有拍摄脚本」 |
| 已经拍好，用户口述了想讲的故事 | **模式 B**：第 0–3 步照常，把故事整理成骨架发布页面（跳过勾选），第 4 步走「有拍摄脚本」 |
| 已经拍好，没有自己的故事 | 原流程：第 4 步你自己写故事 |
| 已经录好旁白（或要先写旁白稿再录） | **旁白片**：第 0–3 步照常，之后按 `references/narration.md`，不走第 4–5.5 步 |

页面的写法、数据库结构、匹配方法都在 `references/shoot_plan.md`。

## 模式 A：拍摄前写脚本

1. **A0 问需求（一次问完）**：去哪、几天、几个人、想讲什么、用什么设备（手机 / 相机 / 无人机 / 稳定器）、大概想剪多长。
2. **A1 写骨架**：按 `references/shoot_plan.md`「写骨架」：一句导演意图，4–7 章，每章 3–8 个镜头；
   需要出镜口播的镜头写口播要点，按约 4 字/秒估时长。要做旁白片时每章再写旁白稿（`lines`，完整句子），见 `references/narration.md`。
3. **A2 发布页面**：复制 `assets/shoot_plan_page.html`、换标题、发布、用 `ArtifactData batch` 写入骨架，把链接给用户。
4. **A3 来回改**：用户在页面上改或在对话里提；你改之前先读，带 `if_version` 写，不覆盖用户的改动。

拍摄时用户在手机上勾选、写备注，不需要你。拍完回来走模式 B。

## 第 0 步：提需求，开工前先问用户（一次问完）

素材目录的绝对路径、一句话背景（去了哪、几天、想讲什么）、要不要 BGM（给歌或让你从
`~/Music/网易云音乐/` 挑本地 mp3/flac/m4a，`.ncm` 不能用）、**故事从哪来**：模式 A 的脚本页面（要链接，
找不到就 `Artifact list` 帮他找）、口述一个故事，还是交给你写；**有没有录好的旁白**（有就走旁白片，要录音文件或目录的路径）。

不问目标时长：成片时长由留下的关键片段决定。用户主动给了时长，才在第 5 步加 `--target`。

## 流程（与 README「工作流」同一套编号）

| 步 | 命令 | 产出 |
|---|---|---|
| 0 提需求 | 问用户，见上 | — |
| 1 盘点 | `probe.py <素材目录>` | `inventory.csv`（clip_id、时长、分辨率）、`silences.json` |
| 2 抽帧打分 | `frames.py --work W`（每 8 秒一帧 + 画面切换处） | `frames.csv`（判糊 / 曝光）、`contact/sheet_*.jpg` 联系表 |
| 3 看懂素材 | `transcribe.py --work W --context "<背景>"`（后台跑）→ **你看联系表写描述**，见下 → `notes.py --work W` → `orient.py --work W ...` | `speech.json`、`scene_notes.json`、`footage_brief.md`、`orientation.json` |
| 4 写故事 | **你来写**，见下；有拍摄脚本时：4a 匹配 → 4b 用户在页面确认 → 4c `match.py --work W` | `story_plan.json`（有脚本时另有 `shoot_plan.json`、`matches.json`） |
| 5 分镜 | `plan.py --work W --dry-run` → 给用户看 → 去掉 `--dry-run`（用户指定了时长才加 `--target 10:00`） | `shots.csv` |
| 5.5 卡点 | 有 BGM 时：`beatsync.py --work W --song 歌.mp3 [--split 3] [--anchor 4:62.5]`，见「精剪」 | 卡点后的 `shots.csv`、`bgm_plan.json` |
| 5.8 字幕 | 有人说话时：**你挑有意义的人声**写 `subtitles.json`，见「字幕与人声」 | `subtitles.json` |
| 6 生成草稿 | 确认剪映已 ⌘Q 退出 → `build.py --work W --name <草稿名> --titles [--bgm-plan W/bgm_plan.json 或 --bgm 歌.mp3] [--subs W/subtitles.json]` | 剪映草稿 + 自检结果 |
| 7 精修导出 | 用户自己在剪映里做（调色、转场、改字幕、导出），你不做 | 成片 |

每步把关键输出（表格、警告）转述给用户；第 5 步 dry-run 的章节表和删除清单必须给用户确认后再落地。

## 第 3 步：看懂素材（你看画面，Whisper 听语音）

1. **语音**：`transcribe.py` 在本地转写，首次运行要下载模型（small 约 500MB），先告诉用户。可中断重跑。
   转写可能有同音字或把环境声听成字，和画面对不上时以画面为准。
2. **画面**：按顺序读 `contact/sheet_*.jpg`，每读几张就把看到的写进 `W/scene_notes.json`，不要全读完才写：
   `{"c001": [{"start": 0, "end": 12, "description": "石阶上山，雾很大"}]}`。时间是素材内秒数，同一段素材内容变了就分条。
   描述写看到的人物、动作、地点、情绪和值得留的瞬间，写具体，第 4 步靠它写故事。
3. **校验**：`notes.py --work W` 列出没写的素材和错误；全部写完后生成 `footage_brief.md`（画面 + 语音）。
   换了会话或上下文被压缩时，先读 `scene_notes.json`，再跑它看还缺什么，接着写。
4. **方向**：看联系表时也留意倒转和歪倒的画面，用 `orient.py` 记录：`--flip` 整段颠倒、`--unusable` 大半歪倒、
   `--bad c005@12` 个别歪帧（秒数照抄联系表）。全部正常也跑一次 `orient.py --work W`，记录已检查过。

联系表默认每 8 秒一帧，外加画面切换处补的帧。某段素材内容看不清时，用 `frames.py --work W --every 4` 抽得更密。
你只看到这些帧，也听不到环境声和音乐；描述里不要写看不到的内容。

## 第 4 步（有拍摄脚本）：把素材对到镜头上，按 references/shoot_plan.md

用户的故事已经在页面上，你不重写故事，只负责把素材对上去：

1. **4a 匹配**：读页面数据；画面镜头比 `scene_notes.json`，口播镜头比 `speech.json` 的文字；写对照建议（带把握和理由）、
   计划外素材建议，上传缩略图，把页面切到剪辑阶段。
2. **4b 用户确认**：请用户在 Mac 上打开页面逐个确认、决定计划外素材、写补充故事。处理补充故事，直到用户说"好了"。
3. **4c 落地**：导出 `W/shoot_plan.json`、`W/matches.json` → `match.py --work W` → `story.py --work W --check`。
   把漏拍、整章删除、待决定的计划外素材转述给用户。之后第 5 步照常。

`match.py` 只认用户确认过的对照，有未确认的就拒绝生成。

## 第 4 步（没有拍摄脚本）：写故事（你的活，按 references/story_plan.md）

1. 读 `W/footage_brief.md`。
2. **先剔除无关素材**：把与主题无关的（日常、别的行程、测试镜头）列出来告诉用户，转换时
   `--exclude c059-c062,...`。拿不准就问用户。同一场景的多条素材可能是不同角度，都保留，取舍由用户决定。
3. 写 `W/story_plan.json`：把关键瞬间写成 `pins`（素材内秒数；自动评分只看画质，看不懂内容），每章定 `rhythm`
   （见「精剪」），然后 `story.py --work W --check --exclude ...`。
4. 用户只要「快速出一版」：`story.py --work W --default --chapters N --exclude ...`。

## 第 5 步：分镜（plan.py 自动做，你负责把关）

`plan.py` 只决定「留哪些镜头、每个镜头取哪段素材的哪里」，章节和素材范围都来自 `story_plan.json`。

**精简模式（默认，不写 `--target`）**：只留关键片段，总时长是结果。

- **本章有 pin 的素材**：只留 pin，不再自动加镜头。hook 借用的素材在它自己的章节仍正常取镜头。
- **其余素材**：按素材长度给额度（`--per-clip N` 可统一指定），取得分最高的窗口，同素材的镜头互相隔开。
- **整段删除**：得分低于 `--min-score`（默认 0.2）、全是坏帧或太短的素材不进成片，dry-run 列出每段的原因。得分是画质在本批素材里的百分位（只看清晰度和曝光，不看内容），所以「得分低」只表示它比同批素材差，不代表它不重要。
- **hook**：只留 pin；没有 pin 就取一个最好的镜头。`share` 被忽略。

删除清单要转述给用户；用户想留某段，就在 `story_plan.json` 给它加 pin 后重跑。

**定长模式（用户指定时长，`--target`）**：总时长精确到微秒。

- **配额**：有 `share` 的章节按比例拿；其余每章保底 20s，剩下按可用时长的平方根分配。

两种模式共用下面的规则（「总时长精确」只属于定长模式）：

- **节奏**：长 12-18s / 短 3-6s / 短 / 中 6-9s 循环；章内大体按拍摄时间，最多挪 2 位避免连续长镜头或三连短镜头；每章最后一个镜头不动（它是这一章的落点）。
- **必选瞬间**：`pins` 最先放，以该瞬间为中心取镜头。
- **挑镜头**：其余镜头取得分最高、不含坏帧的窗口；同一素材复用会降权，区间不重叠，素材首尾 0.5s 不取。
- **切点**：入点 1.5s 内有静音就整体挪过去，少切在半句话上（不判断有没有人说话，见 pitfalls.md「人声分」）。
- **hook 章**放最前当冷开场；带 `intercut` 的章节两条线轮流出镜头。

先 `--dry-run`，把章节表（可用 / 实得时长、镜头数、长/中/短）和删除清单给用户看，确认后再去掉 `--dry-run` 落地。
出现 `⚠ pin … 没放进去 / 放不下` 要告诉用户哪个必选瞬间丢了；用户想换一版镜头时长用 `--seed`。

## 精剪：按故事节奏和 BGM 节奏（你的核心活）

有 BGM 时按这个顺序做：

1. **写故事前先看歌**：`beatsync.py --work W --song 歌.mp3 --analyze` 输出 BPM 和能量段落（`bgm_analysis.json`）。
   能量是这首歌内部相对的 low / mid / high，只说明响度，要结合你对歌的了解或问用户。
   **用哪首、用哪段由你按故事的节奏和情绪判断**：候选歌不必都用，一首歌也不必放完。只把选中的歌传给 `--song`；
   想从歌的中段进，就给成片第一章（或该歌的第一章）加 `--anchor`。你听不到音乐：情绪判断依据是能量段落、BPM、
   你对这首歌的了解（歌名、歌词、风格）；不了解这首歌时，把选择和理由告诉用户，请用户确认。
2. **定故事节奏**：逐个 beat 问「这一拍该冲过去，还是该多停一会让它落地」，写进 `rhythm`。
   `slow` 长镜头为主，`normal` 长短交替，`fast` 短镜头为主，`montage` 整章 2-4s 快切。
   不写时按功能取默认值：hook、escalation 用 `fast`，setup、payoff 用 `slow`，turn 用 `normal`。
3. **定音乐对位**：把 payoff 或最强的 beat 对到 high 段的起点，低能量段留给铺垫。先跑第 5 步看各章时长，
   再用 `--anchor 章号:歌内秒` 落地（章号按成片顺序，hook 是第 1 章）。
4. **卡点并检查**：跑 `beatsync.py`，转述每章的伸缩结果。出现 `⚠` 时按提示调整：
   - 伸缩超过 30%：调整 rhythm、`--per-clip` 或换 anchor，重跑第 5 步和本步。
   - 歌不够长：再选一首情绪合适的歌，用 `--split` 指定换歌的章节，或少留镜头。
   - 丢镜头：把这一章的 rhythm 调慢。
   - 没对上 anchor：高潮没落在预期的音乐位置，换素材更长的收尾镜头或把 anchor 提前，重跑本步。

卡点规则：切点吸附到拍点，章节交界吸附到小节线；成片不会为了放完一首歌而被拉伸：成片与歌尾相差 15% 以内才放到歌尾，否则歌在最近的小节线停住并淡出。
卡点可能挪动镜头时长，关键瞬间靠近镜头边缘时，要核对 pin 还在不在镜头内。

## 字幕与人声

素材里有人说了有意义的话（感慨、对话、叫狗的名字），就让它听得清、看得见：

1. **写故事时就留住这句话**：用 pin 让镜头盖住整句（pin 放在句子中间；句子长就把该章 rhythm 调慢）。
2. **挑句子写 `W/subtitles.json`**，格式同 `speech.json`：`{"c001": [{"start": 0.88, "end": 7.88, "text": "..."}]}`。
   - 只挑有意义的：口头禅、「好，谢谢」、听不清的不要。
   - 改掉同音错字（人名、地名、宠物名先用 `transcribe.py --context` 提示，再手改）；拿不准的句子不配，告诉用户。
   - 一条超过一行（约 20 字）就按语义拆成两条，时间按字数比例分。
   - 有拍摄脚本时，口播镜头（`kind: talk`）对上的那句话默认入选；用口播要点校正 Whisper 的同音字（地名、人名）。
3. `build.py --subs W/subtitles.json`：底部字幕带半透明黑底；说话时 BGM 压到 25%（前后 0.3s 过渡），有字幕的镜头原声开到 100%。
   出现「被剪断了」「不在成片里」的 ⚠，就回第 4 步调 pin。

Whisper 会在风声、安静画面上幻听，最常见的是把 `--context` 原样念出来；`transcribe.py` 已过滤这几类，但和画面对不上的句子仍一律不用。

## 第 6 步：生成草稿注意

- 剪映主进程在跑会被拒绝（它退出时会覆盖打开过的草稿）。请用户 ⌘Q，或经用户同意后代为退出。
- 同名草稿默认拒绝；要重建加 `--replace`（整目录删除后重建）。
- 自检失败（退出码 1）不要交付，按列出的问题修。
- 告诉用户：素材不要移动或改名（草稿里是绝对路径）；转场、调色在剪映里做，字幕文字可以直接在剪映里改。

## 不做

自动导出成片（剪映 7+ 隐藏了导出控件）；读回剪映加密过的草稿；AI 旁白 / TTS；动画 / 特效 / 转场轨（要先实测剪映 11.6 能否加载在线特效资源）；自动降噪。

坑与实测值见 `references/pitfalls.md`。
