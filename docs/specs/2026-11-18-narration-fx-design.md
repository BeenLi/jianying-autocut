# 旁白片的转场、画面特效、滤镜、片头片尾动画 设计

日期：2026-11-18
来源：枸杞岛 v6 之后用户要求加转场和特效。2026-11-18 的 spike 验证过可行性（见第 1 节）。

## 1. 背景与前提

原来的分工是「转场、特效、调色由用户在剪映里做」，因为 pyJianYingDraft 写进去的效果引用的是剪映的在线资源，剪映能不能加载、会不会报草稿损坏，都没有验证过。

**spike 结果**（2026-11-18，剪映 11.8.13532，pyJianYingDraft 锁定在 `69cee12`）：一个 25 秒、5 段的测试草稿，用户打开后：

- 下面这些全部正常加载：转场「叠化」「闪白」（免费）和「星光叠化」（会员）；特效轨「丁达尔光线」（免费）和「胶片闪切」（会员）；片段滤镜「夏日风吟」；视频入场动画「渐显」；字幕入场动画「渐显」。
- **转场不改时间轴**：总长还是 25 秒，各段起点和字幕都还对齐。剪映在切点两侧各借一点画面做过渡，转场图标压在切点正中。旁白和画面的同步不受影响。
- 剪映 11.8 的草稿正文文件叫 `draft_info.json`，旧版叫 `draft_content.json`，库会自己处理。打开过的草稿会被加密，读不回来。

## 2. 目标与验收

用户的决定：

| 问题 | 用户的选择 |
|---|---|
| 转场 / 特效在成片里扮演什么角色 | **只在故事节点加**：章节交界、时间跳跃、场景切换、情绪转折；特效只用于高潮瞬间。其余镜头硬切 |
| 谁来定节点 | **Claude 自动建议，写进编排并附理由，用户在页面上确认**（和 `bgm: up/drop` 一样） |
| 会员资源 | 用户是会员，**都能用**；会员项在 dry-run、build 报告和页面上标出来 |
| 支持哪几类 | 转场、画面特效（独立特效轨）、片头 / 片尾动画、滤镜 |
| 支持哪种剪法 | **只做旁白片**（`narration_plan.json`），镜头片以后再说 |

验收：

- 枸杞岛 v7：Claude 按第 6 节的原则给出建议，用户在页面上确认，生成草稿后在剪映里看，效果都在、位置都对、旁白和画面同步；
- 没有 fx 字段的旧编排生成的草稿，和现在逐字段一致；
- 现有测试全部通过，下面每一节都有新增测试。

不做：

- 镜头片（`story_plan.json` / `plan.py` / `shots.csv` 的格式）；
- 字幕动画；
- 特效、滤镜的参数调节，只用默认参数（滤镜强度除外）；
- 转场的余量检查：剪映从切点两侧借画面，镜头刚好从素材第 0 秒开始、或用到最后一帧时会怎样，在 v7 真机上观察，有问题再加；
- `beatsync.py` 不改，它本来就拒绝处理旁白片。

## 3. 数据格式：`narration_plan.json`

新增 4 个可选字段。没有这些字段时，行为和现在完全一样。

```json
{"intro": {"type": "渐显"},
 "outro": {"type": "渐隐"},
 "items": [
  {"id": "L11", "type": "line", "...": "...",
   "transition": {"type": "叠化", "dur": 0.6, "reason": "第二天一早，时间跳跃"}},
  {"id": "L33", "type": "line", "...": "...",
   "effect": {"type": "冲击波", "reason": "落水那一下"}},
  {"id": "L18", "type": "line",
   "visuals": [{"clip_id": "c074", "at": 15, "filter": {"type": "夏日风吟", "intensity": 60}}]}
 ]}
```

| 字段 | 含义 |
|---|---|
| `item.transition` | **切进这一项时**用的转场：挂在上一项最后一个镜头和这一项第一个镜头之间。`dur` 是秒数，不写就用剪映的默认时长。`line` 和 `live` 都可以写 |
| `item.effect` | 画面特效：放在独立的特效轨上，覆盖这一项从开始到结束（`start_us` 到 `end_us`，也就是 narrate 排出来的整个槽） |
| `visuals[i].filter` | 只给这一个画面加滤镜；`intensity` 0–100，不写就是 100 |
| `intro` / `outro` | 片头第一个镜头的入场动画、片尾最后一个镜头的出场动画 |
| `reason` | Claude 写的理由，页面上显示，不进草稿 |

`type` 填剪映里的中文名，和库里枚举的显示名一致（第 4 节的目录）。

约束：

- 第一项写 `transition`：**报错**（前面没有镜头，应该用 `intro`）；
- 画面留空、延续上一个镜头的项写 `transition`：**警告并忽略**（这里没有切点）；
- 被跳过的项（`skip: true`）身上的 `transition`、`effect` 不生效；
- 一个切点只能有一个转场。上一项是延续的情况下，转场按 narrate 实际切出来的切点来挂。

## 4. 效果目录：`fx_catalog.py` → `assets/fx_catalog.json`

narrate.py 不依赖 pyJianYingDraft，这一点保持不变。新增 `scripts/fx_catalog.py`（依赖锁定版本的库），把库里的枚举导出成 JSON：

```json
{"lib": "pyJianYingDraft@69cee12",
 "transition": {"叠化": {"vip": false, "dur": 0.5}, "星光叠化": {"vip": true, "dur": 0.8}},
 "effect": {"丁达尔光线": {"vip": false}},
 "filter": {"夏日风吟": {"vip": false}},
 "intro": {"渐显": {"vip": false, "dur": 0.5}},
 "outro": {"渐隐": {"vip": false, "dur": 0.5}}}
```

| 类 | 来源枚举 | 条目（免费） |
|---|---|---|
| transition | `TransitionType` | 453（130） |
| effect | `VideoSceneEffectType` | 1097（635） |
| filter | `FilterType` | 1160（258） |
| intro | `IntroType` | 155（38） |
| outro | `OutroType` | 124（21） |

- 键名用枚举成员的**显示名**（`meta.name` / `meta.title`，比如「闪白 II」），不用 Python 成员名（`闪白_II`）。build 时按显示名查回枚举成员。显示名重复的，取第一个，并在生成时打印出来。
- 目录文件提交到仓库。升级库版本时重跑 `fx_catalog.py`。测试会核对目录和当前库一致，不一致就失败。
- Claude 挑效果时也查这份目录。

## 5. 校验与时间换算：`narrate.py`

### 校验（`validate`，`--dry-run` 和正式运行都会做）

| 情况 | 级别 |
|---|---|
| `type` 不在目录对应的类里 | 错误，附上最接近的 3 个候选名（`difflib.get_close_matches`） |
| 第一项写了 `transition` | 错误 |
| `dur` 不是正数 | 错误 |
| `intensity` 不在 0–100 | 错误 |
| 字段不是对象、缺 `type` | 错误 |
| 延续项写了 `transition` | 警告，忽略 |
| 转场 `dur` 大于两侧镜头中较短那个的一半 | 警告，按那一半截短（排完镜头才知道镜头长度，所以在输出阶段检查） |
| 转场超过 8 个、特效超过 3 个 | 提醒（建议原则里的上限，第 6 节） |
| 用到会员项 | 报告里列出：「会员：星光叠化（L11）」 |

### 输出：`narration_track.json` 新增 `fx` 段

```json
"fx": {
  "transitions": [{"at_us": 37500000, "type": "叠化", "dur_us": 600000, "item": "L11", "vip": false}],
  "effects":     [{"start_us": 49200000, "dur_us": 5600000, "type": "冲击波", "item": "L33", "vip": false}],
  "filters":     [{"start_us": 170100000, "type": "夏日风吟", "intensity": 60, "item": "L18", "vip": false}],
  "intro": {"type": "渐显", "vip": false},
  "outro": {"type": "渐隐", "vip": false}
}
```

- `transitions[].at_us`：这一项第一个镜头的 `start_us`，也就是切点时刻；
- `effects[]`：这一项的整个槽 `[start_us, end_us)`；
- `filters[].start_us`：那个画面对应镜头的 `start_us`。一个 visual 只会排出一个镜头；如果回退逻辑换了素材（`fallback`），滤镜跟着这个位置走，并给警告；
- 没有任何 fx 时不写 `fx` 段，旧的 build 读到旧 track 不受影响；
- dry-run 打印里，在对应的项后面附一行，比如「⤷ 转场 叠化 0.6s」「⤷ 特效 冲击波」「⤷ 滤镜 夏日风吟 60」。

shots.csv 的格式不变，它和镜头片的 plan.py 共用。

## 6. 建议原则（写进 `references/narration.md`）

Claude 配完画面以后（N3）再提效果建议，每一条都写 `reason`：

- **转场**只放在故事节点：章节交界；时间跳跃（「第二天一早」「晚上回到民宿」）；场景大切换（船上到岛上）；情绪转折（美景之后突然车坏）。默认用柔和的叠化类；时间跳跃可以用「闪黑」；冲击性的转折用「闪白」。
- **画面特效**只给全片 1–3 个高潮瞬间（落水、最美的那一刻日落）。
- **滤镜**很少用：烧过 LUT、或者用户会在剪映里调色的镜头不加；只在需要明显风格化的地方用（比如回忆片段的复古滤镜）。
- **片头 / 片尾**：冷开场用入场「渐显」，片尾最后一个镜头用出场「渐隐」，这是默认建议。
- 上限：3–4 分钟的片子，转场不超过 8 个，特效不超过 3 个。
- 会员项可以用（用户是会员），但同等效果下优先选免费的，换账号也不会出问题。

## 7. 落地：`build.py`

读 `narration_track.json` 的 `fx`：

| 效果 | 做法 |
|---|---|
| 转场 | 找到主轨上「`start_us + dur_us == at_us`」的片段（切点前那一段），`add_transition(枚举, duration=dur_us)`。找不到就自检失败 |
| 特效 | 有特效时新建一条特效轨「特效」，`script.add_effect(枚举, Timerange(start_us, dur_us), track_name="特效")` |
| 滤镜 | 找到「`start_us` 相等」的片段，`add_filter(枚举, intensity)` |
| intro / outro | 第一个 / 最后一个片段，`add_animation(IntroType / OutroType)` |

- 显示名到枚举成员的查找放在一个小函数里，查不到就报错（正常情况下 narrate 已经拦过了，这里是兜底）。
- **自检新增一项**：草稿里转场、特效、滤镜、动画的数量和名字和 `fx` 完全一致；对不上就算自检失败，退出码 1，草稿不交付。
- 报告：「转场 6 个、特效 2 个、滤镜 1 个、片头片尾动画 2 个；会员：星光叠化（L11）」。
- 没有 `fx` 段时，代码路径和现在完全一样。

## 8. 页面：`assets/shoot_plan_page.html`

数据位置：

| 效果 | 存在哪 |
|---|---|
| transition、effect | `nmatch/<句子id>` 的 `transition` / `effect` 字段（结构同第 3 节） |
| filter | `nmatch/<句子id>.visuals[i].filter` |
| intro、outro | `plan/meta.fx = {"intro": {...}, "outro": {...}}` |

剪辑视图：

- 每句的面板里，有建议时显示效果卡片：「转场：叠化 0.6s　理由：第二天一早，时间跳跃」。会员项带「会员」标签（Claude 写 nmatch 时带上 `vip: true`）。
- 每张卡片可以改名字、改时长 / 强度，也可以去掉。写入时带 `by: "user"`，去掉就是把这个字段删掉。
- 滤镜显示在对应画面的卡片里，和「允许重复用 / 消音」放在一起。
- 左侧清单里，有效果的句子显示一个小标记（比如 ✦），方便扫一眼看出哪些句子有效果。
- 片头 / 片尾显示在剪辑视图顶部，同样可以改、可以去掉。
- 名字合不合法不在页面上查（目录 3000 项太大），交给 narrate 的 dry-run 报。

导出（`references/narration.md` 的「导出」一节补充）：`transition`、`effect`、`visuals[i].filter` 原样带回 `narration_plan.json`；`plan/meta.fx` 写到顶层的 `intro` / `outro`；`vip`、`by` 这些页面字段不带。

## 9. 测试

每项都先写会失败的测试，再实现。

| 模块 | 测试 |
|---|---|
| fx_catalog | 目录和当前库的五个枚举一一对应（数量、显示名、vip）；显示名能查回枚举成员 |
| narrate 校验 | 名字错误时报错并给候选名；第一项写转场报错；延续项写转场给警告；dur ≤ 0 报错；intensity 越界报错；跳过项的效果不生效；旧编排没有新的错误和警告 |
| narrate 输出 | 转场 `at_us` 对准切点（普通句、原声段前后、一句多画面、紧跟在延续项后面）；dur 过长时按一半截短并警告；特效覆盖整个槽；滤镜对到正确的镜头；没有 fx 时不写 `fx` 段 |
| build | 转场挂在切点前那个片段上；特效轨和特效片段存在；滤镜、入场、出场动画在对的片段上；自检能发现数量不一致；没有 fx 时草稿和现在一致 |
| 页面 harness | 效果卡片、理由、会员标签能显示；改名、改时长、去掉时写入的字段正确；滤镜跟着画面走；片头片尾能改；旧数据照常渲染 |
| 真机 | 枸杞岛 v7（第 2 节的验收） |
