# 旁白片的转场、画面特效、滤镜、片头片尾动画 设计

日期：2026-11-18（同日按 Codex 评审修订）
来源：枸杞岛 v6 之后，用户要求加转场和特效。可行性已在 2026-11-18 用 spike 验证（见第 1 节）。

## 1. 背景与前提

原来的分工是：转场、特效、调色都由用户在剪映里做。原因是 pyJianYingDraft 写进草稿的效果引用的是剪映在线资源，剪映能不能加载、会不会报草稿损坏，都没验证过。

**spike 结果**（2026-11-18，剪映 11.8.13532，pyJianYingDraft 锁定在 `69cee12`）。测试草稿 25 秒、5 段，用户打开后的结果：

- 全部正常加载：
  - 转场「叠化」「闪白」（免费）和「星光叠化」（会员）；
  - 特效轨上的「丁达尔光线」（免费）和「胶片闪切」（会员）；
  - 片段滤镜「夏日风吟」；
  - 视频入场动画「渐显」、字幕入场动画「渐显」。
- **转场不改变时间轴**：总长还是 25 秒，各段起点和字幕都对齐。剪映在切点两侧各借一段画面做过渡，转场图标压在切点正中。所以旁白和画面的同步不受影响。
- 草稿正文文件名：剪映 11.8 是 `draft_info.json`，旧版是 `draft_content.json`，库会自动处理。草稿被剪映打开后会加密，读不回来。

库的两个行为决定了 build 的写法（Codex 评审时核对过源码）：

- 片段上的转场、滤镜、动画材料，只在 `script.add_segment()` 那一刻收集进草稿（`_script_file_segments.py:105–124`）。保存时不会再扫描一遍。所以片段入轨之后再挂效果，会产生悬空引用。
- `add_animation(OutroType)` 用「片段长度 − 动画时长」算出场动画的起点（`video_segment.py:646–651`），不会截短。动画比片段长时，起点会是负数。

## 2. 目标与验收

用户的决定：

| 问题 | 用户的选择 |
|---|---|
| 转场、特效在成片里起什么作用 | **只在故事节点加**：章节交界、时间跳跃、场景切换、情绪转折。特效只用在高潮瞬间。其余镜头一律硬切 |
| 谁来定节点 | **Claude 自动建议**，写进编排并附上理由；**用户在页面上逐个确认** |
| 会员资源 | 用户是会员，**都能用**；dry-run、build 报告和页面上会标出会员项 |
| 支持哪几类 | 转场、画面特效（独立特效轨）、片头 / 片尾动画、滤镜 |
| 支持哪种剪法 | **只做旁白片**（`narration_plan.json`） |
| 一个画面被拆成多个镜头时，滤镜加在哪 | 加在**这个画面产出的所有镜头**上；从别的素材借来的镜头不加 |
| 页面上能改什么 | 转场：名字、时长。特效：名字。滤镜：名字、强度。片头 / 片尾：名字。特效固定覆盖整句，不能改时长；动画时长用目录默认值，放不下时自动截短 |
| 页面上换画面时，滤镜怎么办 | 同一素材只改秒数：保留滤镜。换成别的素材：清掉滤镜 |
| 怎样算确认 | **每个效果单独确认**。Claude 新加的建议是「待确认」，用户点确认或改过之后才算确认。**未确认的效果不导出**，Claude 导出时会列出被排除的项 |

验收：

- 枸杞岛 v7：Claude 按第 6 节的原则给出建议，用户在页面上确认后生成草稿。在剪映里检查：效果都在、位置都对，旁白和画面同步；
- 没有任何 fx 字段的旧编排，生成的草稿和现在逐字段一致；
- 现有测试全部通过；下面每一节都有新增测试。

不做：

- 镜头片（`story_plan.json` / `plan.py`）。`shots.csv` 的格式不变；
- 字幕动画；
- 特效、滤镜的参数调节。只用默认参数，滤镜强度除外；
- 转场的余量检查。剪映会从切点两侧借画面，但镜头恰好从素材第 0 秒开始、或用到素材最后一帧时会怎样，还不知道。先在 v7 真机上观察，有问题再加；
- `beatsync.py` 不改，它本来就拒绝处理旁白片。

## 3. 数据格式：`narration_plan.json`

新增 4 个可选字段。没有这些字段时，行为和现在完全一样。**`narration_plan.json` 里只放已确认的效果**：从页面导出时会过滤掉未确认的项；没有页面时，Claude 直接改编排，把 `--dry-run` 结果给用户看，用户认可就算确认（和现在配画面的做法一样）。

```json
{"intro": {"type": "渐显"},
 "outro": {"type": "渐隐"},
 "items": [
  {"id": "L11", "type": "line", "...": "...",
   "transition": {"type": "叠化", "dur": 0.6, "reason": "第二天一早，时间跳跃"}},
  {"id": "L33", "type": "line", "...": "...",
   "effect": {"type": "冲击波", "reason": "落水那一下"}},
  {"id": "L18", "type": "line",
   "visuals": [{"clip_id": "c074", "at": 15, "filter": {"type": "夏日风吟", "intensity": 60}}]}
 ]}
```

| 字段 | 含义 | 可写的键 |
|---|---|---|
| `item.transition` | **切进这一项时**用的转场（`line` 和 `live` 都可以写） | `type`、`dur`（秒，可省，省略时用目录默认值）、`reason` |
| `item.effect` | 画面特效，放在独立特效轨上，覆盖这一项的**最终槽** | `type`、`reason` |
| `visuals[i].filter` | 给这个画面产出的所有镜头加滤镜 | `type`、`intensity`（0–100，可省，省略时为 100）、`reason` |
| `intro` / `outro` | 第一个镜头的入场动画 / 最后一个镜头的出场动画 | `type`、`reason` |

`type` 填剪映里的中文显示名（见第 4 节的目录）。`reason` 只给页面展示用，不进草稿。

字段**是否生效，要等排完镜头才能判断**（第 5 节）。校验阶段只检查格式和名字。

## 4. 效果目录：`fx_catalog.py` → `assets/fx_catalog.json`

narrate.py 现在不依赖 pyJianYingDraft，这一点保持不变。新增 `scripts/fx_catalog.py`，依赖锁定版本的库，把库里的枚举导出成 JSON：

```json
{"lib": "pyJianYingDraft@69cee12",
 "transition": {"叠化": {"member": "叠化", "resource_id": "6724845717472416269", "vip": false, "dur": 0.5}},
 "effect":     {"X-Signal": {"member": "X_Signal", "resource_id": "6709706971638927875", "vip": false}},
 "filter":     {"夏日风吟": {"member": "夏日风吟", "resource_id": "7127684611802418445", "vip": false}},
 "intro":      {"渐显": {"member": "渐显", "resource_id": "6798320778182922760", "vip": false, "dur": 0.5}},
 "outro":      {"渐隐": {"member": "渐隐", "resource_id": "6798320902548230669", "vip": false, "dur": 0.5}}}
```

| 类 | 来源枚举 | 显示名字段 | 条目数（其中免费） |
|---|---|---|---|
| transition | `TransitionType` | `value.name` | 453（130） |
| effect | `VideoSceneEffectType` | `value.name` | 1097（635） |
| filter | `FilterType` | `value.name` | 1160（258） |
| intro | `IntroType` | `value.title` | 155（38） |
| outro | `OutroType` | `value.title` | 124（21） |

- 键用**显示名**，比如「闪白 II」「X-Signal」；`member` 记 Python 成员名，比如「闪白_II」「X_Signal」。build 用 `getattr(枚举, member)` 取成员，**不用**库自带的 `from_name()`：它查的是成员名，`X-Signal` 这种显示名查不到。
- **显示名重名时生成失败**。报错里列出重名的条目，要求在脚本里加显式的消歧规则，比如在显示名后面加后缀。锁定版本中，这五类目前都没有重名。
- 目录文件提交到仓库，升级库版本时重跑一次。测试会核对：每个条目的成员名、resource_id、vip、默认时长都和当前库一致，五类的数量也一致；不一致就失败。
- Claude 挑效果时也查这份目录。

## 5. narrate.py：校验与 `fx` 输出

### 5.1 校验（`validate`，在排镜头之前）

| 情况 | 级别 |
|---|---|
| 字段不是对象，或者缺 `type` | 错误 |
| `type` 不在目录的对应类里 | 错误，附上最接近的 3 个候选名（`difflib.get_close_matches`） |
| 字段里有不认识的键 | 错误，防止拼错的键被悄悄忽略 |
| `dur` 不是正数 | 错误 |
| `intensity` 不在 0–100 之间 | 错误 |
| **第一个没被跳过的项**写了 `transition` | 错误（前面没有镜头，应该用 `intro`） |
| 被跳过的项写了 `transition`、`effect` 或 `filter` | 警告：不生效 |
| 转场超过 8 个、特效超过 3 个 | 提醒（第 6 节的上限） |

### 5.2 计算 fx（**在排镜头的最后一步**）

延续、借画面、零头挤给下一句、J-cut 这些步骤都做完之后，才计算 fx。全部用最终的**整数微秒**，不用 shots.csv 里四舍五入过的 `start_s` / `dur_s`。

排镜头时，每个镜头要记下来源：属于哪一项（`item`）、来自这一项的第几个画面（`vis`；借来的镜头或延长出来的部分记为 `None`）。这样「画面 → 镜头」的对应关系就是直接记录下来的，不靠数组下标去猜。

| 效果 | 什么时候生效 | 挂在哪里 |
|---|---|---|
| 转场 | 第 k 项在最终结果里**至少有一个自己的镜头**，并且它的第一个镜头不是全片第一个镜头。槽太短、被上一句延长吞掉时，第 k 项没有自己的镜头：**警告，忽略**，不会挪到下一个切点去。延续项因为紧跟原声段而借画面、切出了新镜头时，切点是真实存在的，转场照样生效 | 切点时刻 `at_us` = 第 k 项第一个镜头的 `start_us`；记下切点前那个镜头的行号 `shot`（从 1 开始，和 shots.csv 的 `idx` 一致） |
| 特效 | 第 k 项没被跳过 | 第 k 项的**最终槽** `[start_us, end_us)` |
| 滤镜 | 第 k 项第 i 个画面至少产出了一个镜头。一个都没有（被吞掉了）时警告、忽略；被回退逻辑换成本句的其他候选素材时，也给警告 | 这个画面产出的**所有**镜头，每个镜头一条记录 |
| 片头 / 片尾 | 总有第一个和最后一个镜头 | 第一个 / 最后一个镜头 |

**时长解析与截短**：

- 转场：`dur`，省略时取目录默认值，再截到「切点两侧最终镜头中较短那个的一半」。截短时给警告。
- 片头 / 片尾：取目录默认值，截到所在镜头的长度。只有一个镜头、又同时有片头和片尾时，各截到镜头长度的一半，保证两段动画不重叠。截短时给警告。
- 所有时长都在 narrate 里换算成 `dur_us` 写出。build 不再自己取默认值。

### 5.3 输出：`narration_track.json` 新增 `fx` 段

```json
"fx": {
  "transitions": [{"shot": 12, "at_us": 37500000, "type": "叠化", "dur_us": 600000, "item": "L11", "vip": false}],
  "effects":     [{"start_us": 49200000, "dur_us": 5600000, "type": "冲击波", "item": "L33", "vip": false}],
  "filters":     [{"shot": 30, "start_us": 170100000, "type": "夏日风吟", "intensity": 60, "item": "L18", "vip": false}],
  "intro": {"shot": 1, "type": "渐显", "dur_us": 500000, "vip": false},
  "outro": {"shot": 40, "type": "渐隐", "dur_us": 500000, "vip": false}
}
```

- `shot` 是 shots.csv 的行号；`at_us` / `start_us` 让 build 核对这一行的时间对得上，防止旧的 track 配上重新生成的 shots；
- 没有任何生效的 fx 时，不写 `fx` 段；
- dry-run 打印里，在对应的项后面附一行，比如「⤷ 转场 叠化 0.6s」「⤷ 特效 冲击波」「⤷ 滤镜 夏日风吟 60」。被忽略或被截短的效果列在 ⚠ 里；会员项列成「会员：星光叠化（L11）」。

## 6. 建议原则（写进 `references/narration.md`）

Claude 在配完画面（N3）之后再提效果建议，每条都要写 `reason`：

- **转场**只用在故事节点：
  - 章节交界；
  - 时间跳跃，比如「第二天一早」「晚上回到民宿」；
  - 场景大切换，比如从船上到岛上；
  - 情绪转折，比如美景之后突然车坏。

  默认用柔和的叠化类；时间跳跃可以用「闪黑」；冲击性的转折用「闪白」。
- **画面特效**只用在全片 1–3 个高潮瞬间，比如落水、日落最美的那一刻。
- **滤镜**尽量少用：烧过 LUT、或者用户会在剪映里调色的镜头不加；只在需要明显风格化的地方用，比如回忆片段加复古滤镜。
- **片头 / 片尾**：默认建议冷开场用入场「渐显」，最后一个镜头用出场「渐隐」。
- **数量上限**：3–4 分钟的片子，转场不超过 8 个，特效不超过 3 个。
- **会员项**可以用（用户是会员），但效果相当时优先选免费的，这样换账号也不会出问题。

## 7. build.py：落地与自检

**挂效果的时机**：先把 `fx` 整理成「行号 → 这个镜头要挂的效果」。遍历 shots 创建 `VideoSegment` 时，先把这一行的转场、滤镜、入场 / 出场动画都挂上，**再**调用 `script.add_segment()`。挂之前核对：`fx` 里记的 `at_us` 或 `start_us` 要和这一行镜头的时间对得上，对不上就报错退出，提示重跑 narrate。

| 效果 | 调用 |
|---|---|
| 转场 | 在切点前那个镜头（`shot` 行）上 `add_transition(成员, duration=dur_us)` |
| 滤镜 | `add_filter(成员, intensity)` |
| 片头 / 片尾 | `add_animation(IntroType / OutroType 成员, duration=dur_us)` |
| 特效 | 有特效时新建特效轨「特效」，调用 `script.add_effect(成员, Timerange(start_us, dur_us), track_name="特效")` |

显示名到枚举成员的查找用目录里的 `member` 字段，查不到就报错。正常情况下 narrate 已经先拦住了，这里是兜底。

**自检新增一项「效果逐个对上」**。读回保存好的草稿，沿主轨逐个片段核对：

- 转场：片段引用的转场材料，名字、`resource_id`、时长都和预期一致，并且挂在预期的片段上；
- 滤镜：名字、`resource_id`、强度和预期一致，并且挂在预期的片段上；
- 动画：入场 / 出场的名字、起点、时长和预期一致，并且**落在片段范围内**（起点 ≥ 0，终点 ≤ 片段长度）。动画材料在 `materials.material_animations[].animations` 里，一个片段同时有入场和出场时，是一个材料里的两个条目；
- 特效轨：每个特效片段的时间范围和 `material_id` 都对得上 `materials.video_effects` 里的条目，名字、`resource_id` 和预期一致；
- 悬空引用检查补上特效轨片段的 `material_id`（现在只检查了 `extra_material_refs`）。

任何一项对不上都算自检失败：退出码 1，草稿不交付。

报告示例：「转场 6 个、特效 2 个、滤镜 1 个、片头片尾动画 2 个；会员：星光叠化（L11）」。

没有 `fx` 段时，代码路径和现在完全一样。

## 8. 页面：`assets/shoot_plan_page.html`

### 数据位置

| 效果 | 存在哪 |
|---|---|
| 转场、特效 | `nmatch/<句子id>` 的顶层字段 `transition` / `effect` |
| 滤镜 | `nmatch/<句子id>.visuals[i].filter` |
| 片头、片尾 | `plan/meta` 的顶层字段 `intro` / `outro`（分成两个字段，改其中一个不会覆盖另一个） |

每个效果对象的结构：`{type, dur?, intensity?, reason?, vip?, confirmed, by}`。

- `confirmed`：Claude 写建议时设为 `false`；用户点「确认」，或者改过名字、时长、强度，就变成 `true`；
- `by`：`"claude"` 或 `"user"`，表示谁最后改的；
- `vip`：Claude 写建议时，按目录填上。用户在页面上改了名字后，`vip` 写成 `null`，页面显示「会员？」，以 dry-run 的报告为准（页面上不加载 3000 项的目录）。

**去掉一个效果**：把字段写成 `null`，比如 `{transition: null}`。页面用的是 `update`，只改一个字段，不会动同一文档里的其他字段。导出时跳过 `null`。Claude 之后重新提建议时，**不要覆盖值为 `null` 的字段**，那是用户主动去掉的。只有用户在对话里明确要求时才重新加。

**滤镜嵌在 `visuals` 数组里**：每次写 `visuals` 都是整个数组一起写。所以「换画面」（`reassign-n`）、勾选「重复用 / 消音」、改滤镜，三条写入路径都要从现有的 `visuals` 出发修改，不能重新拼一个新数组。规则：

- 同一素材只改秒数：保留 `filter`、`reuse`、`mute`；
- 换成别的素材：清掉这三个。

### 剪辑视图

- 每句的面板里，有效果就显示一张卡片，比如「转场：叠化 0.6s　理由：第二天一早，时间跳跃」，旁边是状态：「待确认」或「已确认」。会员项加「会员」标签。
- 卡片上的按钮：
  - **确认**；
  - **改**：转场能改名字和时长，特效能改名字，滤镜能改名字和强度，片头片尾能改名字；
  - **去掉**。
- 滤镜显示在对应画面的卡片里，和「允许重复用 / 消音」放在一起。
- 句子本身的确认状态（`nmatch.confirmed`）和效果的确认状态是分开的。左侧清单里：有效果的句子带一个小标记 ✦；有待确认效果的句子，这个标记显示成黄色。
- 片头、片尾放在剪辑视图顶部，操作方式和其他效果一样。
- 页面不检查名字是否合法，交给 narrate 的 dry-run。

### 导出（`references/narration.md` 的「导出」一节要补充）

- 除了 `chapters`、`lines`、`nmatch`，还要读 `plan/meta`；
- 按白名单导出：
  - `transition` 只导出 `type`、`dur`、`reason`；
  - `effect` 只导出 `type`、`reason`；
  - `filter` 只导出 `type`、`intensity`、`reason`；
  - `intro`、`outro` 只导出 `type`、`reason`；
  - `vip`、`by`、`confirmed` 一律不导出；
- **只导出 `confirmed === true` 的效果**。值为 `null` 和未确认的都跳过。Claude 把被跳过的未确认效果列给用户看。
